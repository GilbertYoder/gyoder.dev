The frontend is what users see. Slow, confusing, or broken user interfaces damage retention, frustruate users, and outweigh any amount of time put into backend logic.

I build interfaces that are fast, responsive, and maintainable. That could be a single-page static site or a dashboard your team uses all day.

## What I build

- Static websites and landing pages
- Web apps and internal tools: dashboards, admin panels, forms, complex workflows
- Rebuilds of sites that have become slow, outdated, or unmaintainable
- Reusable components so your UI stays consistent as it grows

## How I work

- **Start with the workflow.** Before designing anything, I determine user intentions so I can cut unnecessary steps and remove the possibility of state conflicts. This ties in with the backend data model so is often done before backend work.
- **Performance and accessibility.** Fast load times, semantic HTML, keyboard support, and readable contrast.
- **The proper tools.** Not every page needs a fat JavaScript framework. Less code *can* mean faster pages and less to maintain. (Though not always!)
- **Maintainable.** Clean, typed, well-organized code, so the next developer can pick it up without huge onboarding costs.

## Tools I use

TypeScript, React, Lit, Vite, or plain old HTML and CSS
